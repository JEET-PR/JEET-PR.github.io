题目描述

哈基米发明了一种无损压缩算法：

对于任意正整数序列 $A = (A_1, A_2, \ldots, A_n)$，按照从 $i$ 从小到大依次处理 $A$，其中 $w$ 的初始值为 0：

  • 若 $i = 1$ 或 $A_i \neq A_{i-1}$，压缩结果增加一项 $[A_i, w]$，并将 $w$ 置 1
  • 若 $i \neq 1$ 且 $A_i = A_{i-1}$，$w$ 增加 1

例如，$A = (1, 1, 1, 3, 3, 2)$ 可以被压缩为 $[1, 3], [3, 2], [2, 1]$。

现在，在压缩结果中有 $n$ 项，请计算原数列中第 $x$ 项（即 $A_x$）的值。

输入输出格式

输入格式

第一行为一个正整数 $n$。

接下来 $n$ 行，每行两个正整数 $v_i, l_i$，表示压缩结果中的一项。

接下来一行一个正整数 $T$，表示询问的个数。

接下来 $T$ 行，每行一个正整数，表示一个 $x$。

输出格式

输出 $T$ 行，每行一个整数，表示 $A_x$ 的值。

问题分析

压缩算法原理

根据题目描述，压缩算法的核心思想是将连续相同的数字合并为一个压缩项：

  1. 当遇到一个新的数字（与前一个不同或为第一个数字）时，创建一个新的压缩项 [当前数字, 1]
  2. 当遇到连续相同的数字时，只增加计数器而不创建新的压缩项

压缩结果中的每个项 [v_i, l_i] 表示原序列中有连续 l_i 个 v_i 数字。

压缩算法示意图

flowchart
  startNode["开始"]
  decisionNode["i=1或A_i≠A_{i-1}?"]
  addItemNode["添加项[A_i,1],w=1"]
  incrementWNode["w=w+1"]
  nextElementNode["继续处理下一个元素"]
  processCompleteNode["处理完所有元素?"]
  endNode["结束"]
  
  startNode --> decisionNode
  decisionNode -->|"是"| addItemNode
  decisionNode -->|"否"| incrementWNode
  addItemNode --> nextElementNode
  incrementWNode --> nextElementNode
  nextElementNode --> processCompleteNode
  processCompleteNode -->|"是"| endNode
  processCompleteNode -->|"否"| decisionNode

原序列与压缩项的对应关系

假设压缩结果为 [(v_1, l_1), (v_2, l_2), ..., (v_n, l_n)]，则原序列的结构如下：

压缩项 对应原序列区间 原序列元素
[v_1, l_1] [1 \sim l_1] [v_1, v_1, \ldots, v_1] (共 [l_1] 个)
[v_2, l_2] [l_1+1 \sim l_1+l_2] [v_2, v_2, \ldots, v_2] (共 [l_2] 个)
[\ldots] [\ldots] [\ldots]
[v_n, l_n] [l_1+\ldots+l_{n-1}+1 \sim L] [v_n, v_n, \ldots, v_n] (共 [l_n] 个)

原序列的总长度为：

[
L = \sum_{i=1}^{n} l_i = S[n]
]

其中 ( S[n] ) 是前缀和数组的最后一个元素，即前 ( n ) 个压缩项的总长度。

算法设计

问题转化

我们需要解决的问题是：给定一个询问位置 x，找出它在原序列中对应的数字。

由于原序列是由多个连续相同数字的段组成的，我们可以将问题转化为：

  1. 确定 x 所在的连续段
  2. 返回该段对应的数字

前缀和与二分查找

为了高效地确定 x 所在的连续段，我们可以使用前缀和数组和二分查找：

  1. 构建前缀和数组：计算每个压缩项对应的原序列结束位置

    定义前缀和数组 $S$，其中：

    $ S[0] = 0 \\ S[i] = S[i-1] + l_i, \quad i = 1, 2, \ldots, n $

    等价地：

    $ S[i] = \sum_{j=1}^{i} l_j, \quad i = 1, 2, \ldots, n $

    其中：

    • $l_j$ 表示第 $j$ 个压缩项的长度
    • $S[i]$ 表示前 $i$ 个压缩项在原序列中占据的总长度

    例如，对于压缩项 $[1,3], [3,2], [2,1]$，前缀和数组为 $S = [0, 3, 5, 6]$。

  2. 二分查找：对于每个询问 $x$，使用二分查找定位其所在的压缩项

    我们需要找到最小的 $k$ 满足：

    $ S[k-1] < x \leq S[k] $

    其中 $1 \leq k \leq n$。此时：

    • 原序列第 $x$ 项属于第 $k$ 个压缩项
    • 对应的数值为 $v_k$（第 $k$ 个压缩项的数值部分）

    这一结论成立的原因：

    • 前 $k-1$ 个压缩项共占据原序列的前 $S[k-1]$ 个位置
    • 第 $k$ 个压缩项占据原序列的位置范围为 $(S[k-1], S[k]]$
    • 因此，原序列第 $x$ 项必属于第 $k$ 个压缩项

算法流程

flowchart TD
    A[读取输入数据] --> B[构建前缀和数组]
    B --> C[读取询问数量T]
    C --> D{处理所有询问?}
    D -->|是| E[结束]
    D -->|否| F[读取当前询问x]
    F --> G[二分查找确定x所在的压缩项]
    G --> H[输出对应的数字]
    H --> D

具体步骤：

  1. 读取输入数据
  2. 构建前缀和数组
  3. 对于每个询问，使用二分查找确定所在的压缩项
  4. 输出对应的数字

代码实现

代码解析

数据读取优化

由于输入数据可能较大，我们使用了 sys.stdin.read().split() 一次性读取所有输入，然后通过指针 ptr 来遍历数据。这种方式比逐行读取更高效，特别是在处理大量数据时。

前缀和数组构建

  • prefix 数组的长度为 n + 1
  • prefix[0] = 0，表示前0个压缩项的总长度为0
  • prefix[i] 表示前i个压缩项的总长度

二分查找实现

我们使用 Python 标准库中的 bisect_left 函数来实现二分查找：

  • bisect_left(a, x) 返回在有序列表 a 中插入 x 的位置，使得插入后列表仍然有序
  • 对于我们的前缀和数组，bisect_left(prefix, x) 返回的是第一个大于等于 x 的元素的索引，即 x 所在的压缩项的索引

时间复杂度分析

预处理阶段

构建前缀和数组需要遍历所有 $n$ 个压缩项，每个压缩项只需常数时间处理，因此时间复杂度为：

$ \Theta(n) $

查询阶段

对于每个查询，我们使用二分查找算法在长度为 $n+1$ 的前缀和数组中查找位置：

  • 单个查询的时间复杂度为 $\Theta(\log n)$
  • 共有 $T$ 个查询，因此查询阶段的总时间复杂度为：

$ \Theta(T \log n) $

整体时间复杂度

将预处理阶段和查询阶段的时间复杂度相加，得到整体时间复杂度：

$ \Theta(n + T \log n) $

算法效率评估

根据题目给定的约束条件：

  • $1 \leq n \leq 10^3$
  • $1 \leq T \leq 10^4$

计算可得：

  • 预处理阶段操作次数约为 $10^3$ 次
  • 查询阶段操作次数约为 $10^4 \times \log_2(10^3) \approx 10^4 \times 10 = 10^5$ 次
  • 总操作次数约为 $1.1 \times 10^5$ 次，这在现代计算机上可以在毫秒级完成，因此算法非常高效

空间复杂度分析

  • 存储压缩项的空间复杂度为 $O(n)$
  • 存储前缀和数组的空间复杂度为 $O(n)$
  • 整体空间复杂度为 ( O(n) )

算法优化

内存优化

在代码中，我们只存储了压缩项的 v 值和前缀和数组，没有存储 l 值，因为 l 值只在计算前缀和时使用。这样可以节省一些内存空间，特别是当压缩项数量较大时。

输入处理优化

使用 sys.stdin.read().split() 一次性读取所有输入，然后通过指针遍历，可以避免多次 I/O 操作，提高输入处理的效率。

总结

本问题通过分析压缩算法的原理，将原序列分解为多个连续相同数字的段，然后使用前缀和数组和二分查找来高效地处理查询。算法的时间复杂度为 ( O(n + T \log n) )，空间复杂度为 ( O(n) )，能够有效地处理题目给定的数据范围。

这种算法思想在处理连续区间查询的问题中非常常见，通过预处理和二分查找可以将原本需要线性时间的查询优化到对数时间，提高了算法的效率。
