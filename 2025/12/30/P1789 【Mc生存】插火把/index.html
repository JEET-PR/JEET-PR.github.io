P1789 【Mc生存】插火把

题目描述

话说有一天，linyorson 在"我的世界"中开了一个 $n \times n$ 的方阵。现在他有 $m$ 个火把和 $k$ 个萤石，分别放在 $m$ 和 $k$ 的位置。已知没有光并且没放东西的地方会生成怪物，请问在这个方阵中有几个点会生成怪物？

注意：在本题中火把与萤石的照明范围与原版 Minecraft（我的世界）不尽相同，请以本题中的描述为准。

第一行为三个正整数 (n)、(m) 和一个非负整数 (k)。

第二到第 (m + 1) 行每行两个正整数 (x)，(y)，表示各个火把的位置。

第 (m + 2) 到第 (m + k + 1) 行每行两个正整数 (x)，(y)，表示各个萤石的位置。

数据中可能没有萤石，但一定有火把。

说明/提示

数据保证 (1 \leq n \leq 100)，(1 \leq m \leq 100)，(0 \leq k \leq 100)，(1 \leq x, y \leq n)。

问题分析

问题建模

我们需要解决的问题是在一个 (n imes n) 的网格中，放置火把和萤石后，计算有多少个位置会生成怪物（即没有被照亮且没有放置物品的位置）。

照明范围分析

  1. 火把的照明范围：

    • 以火把为中心的 5x5 区域
    • 具体照明位置为：
      • 水平方向：火把正上方和正下方2格
      • 垂直方向：火把左右各2格
      • 对角线方向：火把周围1格的十字区域
    • 可以用数学公式表示为：对于火把位置 ((x, y))，位置 ((i, j)) 会被照亮当且仅当：
      $(|i - x| = 2 \land |j - y| = 0) \lor (|i - x| = 1 \land |j - y| \leq 1) \lor (|i - x| = 0 \land |j - y| \leq 2)$

  2. 萤石的照明范围：

    • 以萤石为中心的 5x5 区域
    • 所有位置都是亮的
    • 可以用数学公式表示为：对于萤石位置 ((x, y))，所有满足 (|i - x| \leq 2) 且 (|j - y| \leq 2) 的位置 ((i, j)) 都会被照亮。

算法思路

  1. 初始化网格：创建一个 (n imes n) 的网格，初始状态为未被照亮且未放置物品。
  2. 处理火把：遍历每个火把的位置，根据火把的照明范围更新网格。
  3. 处理萤石：遍历每个萤石的位置，根据萤石的照明范围更新网格。
  4. 标记物品位置：将放置火把和萤石的位置标记为已放置物品。
  5. 计算怪物生成位置：遍历整个网格，统计未被照亮且未放置物品的位置数量。

数学公式

照明范围的数学表示

设物品位置为 ((x_0, y_0))，网格中的任意位置为 ((x, y))：

  1. 火把照明条件：
    $ (|x - x_0| = 2 \land |y - y_0| = 0) \lor (|x - x_0| = 1 \land |y - y_0| \leq 1) \lor (|x - x_0| = 0 \land |y - y_0| \leq 2) $

  2. 萤石照明条件：
    $|x - x_0| \leq 2 \land |y - y_0| \leq 2$

网格坐标转换

由于题目中的输入是从 1 开始计数的，而 Python 中的列表是从 0 开始计数的，因此需要进行坐标转换：

  • 输入坐标：$(x, y)$（1-based）
  • 转换后坐标：$(x-1, y-1)$（0-based）

算法设计

数据结构选择

  • 网格表示：使用一个二维列表 grid，其中每个元素可以是以下三种状态之一：
    • 0：未被照亮且未放置物品
    • 1：被照亮
    • 2：放置了物品（火把或萤石）

算法流程

flowchart TD
    A[输入n, m, k] --> B[初始化n×n网格为0]
    B --> C[处理火把位置]
    C --> D[处理萤石位置]
    D --> E[标记物品位置]
    E --> F[统计怪物生成位置]
    F --> G[输出结果]

照明范围处理

  1. 火把照明范围处理：

    • 对于每个火把位置 ((x, y))，遍历以 ((x, y)) 为中心的 5x5 区域
    • 对于每个位置 ((i, j))，检查是否在网格范围内
    • 如果满足火把照明条件，则将该位置标记为被照亮

  2. 萤石照明范围处理：

    • 对于每个萤石位置 ((x, y))，遍历以 ((x, y)) 为中心的 5x5 区域
    • 对于每个位置 ((i, j))，检查是否在网格范围内
    • 如果满足萤石照明条件，则将该位置标记为被照亮

  • 遍历以火把为中心的 5x5 区域（(i) 和 (j) 从 -2 到 2）

    • 垂直方向上，火把左右各2格的直线区域

复杂度分析

时间复杂度

  1. 初始化网格：(O(n^2))
  2. 处理火把：每个火把需要处理 25 个位置（5x5 区域），因此总时间为 (O(m imes 25))
  3. 处理萤石：每个萤石需要处理 25 个位置，因此总时间为 (O(k imes 25))
  4. 标记物品位置：(O(m + k))
  5. 统计怪物数量：(O(n^2))

由于 $n$、$m$、$k$ 的最大值都是 100，因此总时间复杂度为：
$O(n^2 + m + k) = O(100^2 + 100 + 100) = O(10200) = O(1)$（常数时间）

空间复杂度

  1. 网格存储：(O(n^2))
  2. 火把和萤石位置存储：(O(m + k))

总空间复杂度为 (O(n^2 + m + k) = O(100^2 + 100 + 100) = O(10200) = O(1))（常数空间）

测试用例分析

输入样例

测试用例解释

  • 网格大小为 5x5
  • 放置了一个火把在位置 (3, 3)（1-based）
  • 没有萤石

处理过程

  1. 火把的位置转换为 0-based 坐标 (2, 2)
  2. 火把的照明范围覆盖了大部分 5x5 区域，除了四个角
  3. 火把位置被标记为放置了物品
  4. 统计未被照亮且未放置物品的位置数量

输出结果

  • 总共有 12 个位置会生成怪物

总结

本文详细介绍了洛谷 P1789 【Mc生存】插火把题目的解法。通过分析火把和萤石的照明范围，我们设计了一个暴力枚举的算法，遍历每个物品的照明范围并更新网格状态，最后统计怪物生成位置的数量。

算法的时间复杂度和空间复杂度都是常数级别的，因为题目中给出的数据规模较小（(n \leq 100)，(m \leq 100)，(k \leq 100)）。这种暴力枚举的方法简单直观，易于理解和实现，非常适合处理这类规模较小的问题。

在实现过程中，需要注意坐标转换（从 1-based 到 0-based）和照明范围的正确处理，特别是火把照明范围中四个角的排除。
